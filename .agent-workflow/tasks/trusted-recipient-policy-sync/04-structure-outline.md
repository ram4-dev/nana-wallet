Derive retained baseline from durable consent provenance, never from arbitrary current remote allowlist. Preserve 0.01 SOL ordinary-transfer cap, separately approved delegated limits/expiry, policy ID, signer and unrelated signers. Unknown remote rule/owner/attachment drift blocks mutation.
Consent bootstrap: retained self comes only from the active signer_grants enrollment consent snapshot; Test1 comes from its active confirmed contact ID/version. Remote GET is observed/applied state, never consent; unknown extras block and are never copied into desired state. Replace preparePermission stale pending-policy reuse with composed revision/readback verification. All contact/enrollment/grant create/revoke/expiry writers route through this composer; unsupported paths fail visibly rather than retaining a second full-rule writer.
Concurrency: database-backed lock across backend and worker with bounded calls and revision verification; durable desired/applied revisions. No stale writer may overwrite newer applied policy. Persist intent plus recipient changes in one transaction; remote I/O outside that contact transaction. Decide exact lock/lease implementation in SDD technical design and verify crash behavior before deployment.
Removal transaction: resolve affected grants and acquire their existing claim/revoke locks plus wallet serialization in one globally documented order compatible with every existing writer. Atomically archive/edit contact, revoke each affected whole grant, append each revoke audit, and increment desired policy revision/outbox. Revoke affected active grants; for a grant containing multiple addresses, revoke the entire grant rather than inventing narrower consent. Preserve unrelated grants. Explicitly report affected automatic-payment grants in UI/agent proposal. Do not migrate grants to the replacement address. Invalidate stale selections/previews through version validation.
Empty composition: retain restrictive policy; prove supported deny behavior before using empty rules. Never detach to unrestricted authority. No-wallet contacts remain saved/not enabled.
Checks additionally include concurrent delegated claim/removal, crash at transaction boundaries and deadlock/lock-order tests. Checks: unit composer and provenance; DB tests atomicity, duplicates, same-address aliases, multi-recipient grant revocation, cross-user access, two-process contention, restart, stale revision; adapter fake transport readback and unknown drift. ## Slice 2 — Apply and reconcile signed remote policy
Outcome: immediate bounded attempt after save plus durable retries; verified readback updates applied revision, allowlisted_recipients and policy_hash consistently.
Files: common policy reconciler/runtime, signer adapter wiring, src/server.ts and src/livekit/worker.ts; existing signer and compose deployment documentation/config without secrets.
Shared-policy execution invariant: delegated coverage/claim requires the wallet verified applied revision/hash matching the intended effective policy (or equivalent atomic invalidation of every affected grant binding), not provider_policy_id alone. Ambiguous PATCH, mismatched readback, unknown rules/owner/attachment block all affected automatic executions including siblings until verified reconciliation. This extends existing delegated readiness, not an ordinary-transfer local policy gate. Test sibling grant after timeout, mismatch and foreign rule. Statuses: saved/not configured, pending, syncing, applied, retryable failure, blocked conflict/configuration. Ambiguous PATCH is unverified; GET before retry. Newer desired version after readback stays pending. Recovery after restart uses the same provenance/composer. Removing contact locally is not announced as remote revocation until readback.
Runtime: backend needs its own reachable signed-authorization capability; existing worker loopback endpoint is not backend loopback. Provision only via already-authorized opaque injection, keep key in dedicated signer, verify auth without exposing secret/signature values. No credential modification.
Checks: real adapter over fake transport timeout before/after PATCH, mismatched readback, unreachable signer, foreign signer/owner; DB reconciliation restart and duplicate events; container capability smoke. Stop on unknown remote policy before mutation.

## Slice 4 — Text and voice agent vertical flow
Outcome: user can add/edit/remove trusted recipients by request; same service, consent and policy results as screen.
Files: src/agent/definition.ts, instructions.ts, wallet-agent.ts; src/memory/tools.ts, service.ts; src/conversations/session-state.ts; LiveKit action evidence binding and realtime tool projection.
Replace EVM validation with Solana for recipient drafts/writes/selected-address lookup. Keep unrelated fact memory behavior separate. Resolve contacts by version and ask when ambiguous. Never derive an address from a name. A staged action contains exact immutable identity/address/change, effect on automatic-payment grants, expiry and user binding. Authenticated later affirmative authorizes only that action once; handle final-transcript delay; cancel/expire/replacement/duplicate tools fail closed. Do not count model arguments or voice user-turn counters as evidence. One per-session confirmation arbiter owns the only active authorization window, keyed by {kind: transfer|contact, actionId, userId, createdAt} and immutable proposal/preview version. Opening a conflicting kind fails closed until explicit cancellation/replacement; parallel transcript listeners cannot independently authorize actions. Only the matching tool consumes evidence once. Text uses equivalent action-ID/user/version binding. No shared affirmative authorizes both a contact change and transfer. Test collisions in both opening orders, late events, replay and foreign session/speaker.
Voice address-review channel: persist a server-owned contact-action proposal and publish an authenticated proposal card to the bound conversation UI with exact address/action/version and revocation effects. Open the contact voice authorization window only after successful publication of that immutable proposal. This is publication evidence, not proof the user read it. Transfer address suppression remains intact. A valid explicit pasted/scanned address is required for creation/address replacement; never accept an inferred or spoken-only address from the model. Without a bound visual client or verified address source, refuse permission creation and request the missing review/source. Extend backend/frontend contract and UI card within this slice. Live-session tests prove absent card or unverified address cannot execute.
Checks: agent unit and parity tests, text E2E with real service/DB/adapter; LiveKit session E2E drives actual listener with fake transport, authenticated/foreign/no speech/pre-proposal/final delay/replay and transfer/contact collisions; agent evals. No existing transfer-gate regression.
