These contracts refine approved design revision 3 and outline revision 2. Implementation paths are relative to the authorized worktree. They authorize no remote action during planning or local verification.

## 1. Dormant expansion and source state (L1–L2, L5–L6)

Reserve monotonically ordered migration names at apply time. First candidates, subject to recheck, are `supabase/migrations/20261023000000_embedding_foundation.sql` and `src/db/migrations/018_embedding_foundation.sql`. Subsequent work units append separate pairs; do not expand a migration already integrated into a parent PR. Each pair has equivalent SQL; never apply both chains to one database.

Add `embedding_generation bigint NOT NULL DEFAULT 0 CHECK (embedding_generation >= 0)`, protected `embedding_incarnation uuid NOT NULL DEFAULT extensions.gen_random_uuid()`, nullable `desired_embedding_revision text`, and `embedding_state text NOT NULL DEFAULT 'pending' CHECK (... IN ('pending','ready','failed','inactive'))` to BOTH source tables. U1.1 adds metadata/control while retaining existing NOT NULL constraints. Only U1.4 makes actual `embedding` and `embedding_model_revision` nullable, after U1.3 installs dormant compatibility guards: inactive writes must still supply a valid legacy vector and actual revision. This prevents partial nullable rollout from exposing NULL candidates to old readers. Once activated, guards derive pending metadata and accept vector-free business inserts. Preserve every existing value, version, timestamp and history entry. A ready constraint requires valid nonzero 384-vector and actual=desired revision. Pending legacy rows may still carry their true old vector while dormant; new readers never select it.

Private schema `embedding_private` holds a singleton control row: `activated=false`, `claims_enabled=false`, `semantic_enabled=false`, fixed target revision, run token/expiry, global pause code, and durable budget counters. No client/app access. Never enable activation in a migration default. Lifecycle trigger functions return unchanged legacy writes while dormant after validating their vector/revision compatibility; they never clear/relabel those vectors. Schema/proof layers remain harmless to legacy readers and vector-writing clients.

Once activated, BEFORE INSERT/UPDATE derives all metadata from source content and control state. INSERT sets incarnation, generation1, target and pending (or inactive). Content changes (`name, description` or `fact`), archive/reactivation, and authorized target changes increment generation, clear vector/actual revision and set pending/inactive. Address/provenance-only changes do not re-embed; existing business version rules still apply. Owner/ID changes are rejected after activation. AFTER source mutation creates unique current work `(kind, owner, source_id, incarnation, generation, revision)` or supersedes old work. Archive cancels old work even when business version is unchanged. DELETE cancels/revokes old job tokens; reinsertion with reused ID gets a fresh incarnation.

Indexing completion updates only vector/actual revision/state. It MUST NOT write source `updated_at`, business versions, recipient_versions, policy state, sync intents, proposals, grants or confirmation fields. Triggers watch relevant content/status/revision changes; metadata-only completion cannot enqueue itself. Source/job persistence is one transaction: queue errors abort the business save.

Activation replaces broad recipient_app INSERT/UPDATE table grants with enumerated business-column grants on both tables, preserving existing SELECT/DELETE and forced RLS policies. Source ID/incarnation/owner/metadata cannot be changed through normal UPDATE; source INSERT permits owner and existing business fields only. Existing `app.user_id` transaction-local context remains authoritative; never substitute `auth.uid()`. Column privilege tests must cover every existing policy/contact/proposal writer. Trusted SQL inserts receive automatic indexing without gaining payment authority.

## 2. Jobs and RPC surface (L3–L5)

Jobs contain references, not text/address copies: UUID job ID, fixed kind (`recipient|fact`), owner/source/incarnation/generation/revision, state (`pending|leased|done|failed|superseded`), attempts, available_at, token/lease_until, sanitized error_code and timestamps. Index due jobs and source tuple. Revoke PUBLIC/anon/authenticated/recipient_app schema/table/sequence/function privileges. Privileged functions in public are SECURITY DEFINER with `search_path=pg_catalog,extensions`, fully qualified objects/operators and fixed kind branches, not caller-provided SQL/table identifiers. Revoke PUBLIC execution in the same migration transaction. Grant only worker RPC signatures to `service_role` when present and an isolated NOLOGIN `embedding_worker` test role; neither gets arbitrary source mutation privileges. Verify function-owner RLS bypass explicitly on PG16 and hosted PG17; normal source access retains forced RLS.

Concrete RPC names/arguments:

- `embedding_begin_drain()` returns one run token/90s lease, or deferred if disabled/paused/leased.
- `embedding_claim_jobs(run_token, requested_limit)` caps at four; SKIP LOCKED, job-only locks, 90s lease, random claim token; commit before reading/inference. Expired jobs may be reclaimed with new token. Claiming itself does not consume provider attempts.
- `embedding_read_job(job_id, claim_token)` returns allowlisted name/description OR fact plus exact identity only if current unexpired tuple matches. One SQL snapshot; no retained transaction. Never returns addresses/provenance.
- `embedding_admit_request(scope, byte_count)` atomically reserves global request/byte capacity and bounded in-flight slots; drain also requires a current run. `embedding_start_attempt(job_id, claim_token)` consumes one attempt immediately before a provider request, never before budget admission.
- `embedding_complete(job_id, owner, kind, source_id, incarnation, generation, revision, claim_token, vector)` locks source first, job second; checks every identity field, active status, desired revision, live job/run leases and normalized valid vector; updates source plus job atomically, returning applied/stale. Wrong tuple has no side effect.
- `embedding_fail(same_identity, claim_token, error_code, retry_after_seconds)` uses the same source-before-job order. It never marks a newer row failed. `embedding_pause(run_token, safe_code)` records global auth/quota/config failure; release/defer leased work without spending its unused attempts. `embedding_retry(kind, owner, source_id, expected_generation)` is operator-only and advances indexing generation explicitly; no business authorization change.

Invalidation already owns the source lock before touching jobs. Completion/failure use that order. Claim/admission never wait for source locks while retaining job locks across calls; no transaction remains open over HTTP. A content snapshot becoming stale during HTTP is harmless because completion rechecks under locks. An expired run cannot publish even if the job token has not yet been replaced. Rollback preserves atomic job/source state.

Transient timeout/network/429/5xx: available_at = now + bounded `max(Retry-After, jittered exponential)`; base5s, exponent attempts-1, cap300s, jitter0–20%, clamp final delay to300s. Maximum five started provider attempts per generation. Invalid input/vector/oversize is terminal for that generation. Provider 401/403/quota/config errors pause globally for operator repair, instead of exhausting every source. Local attempt/time limits do not promise indexing within one minute. Operator is the deployment maintainer; diagnostics expose failed-count/oldest-age/safe code. No automatic reset of wallet or retry authority.

## 3. Model and endpoint contracts (I1–I5)

Identity literal: `openai:text-embedding-3-small:384:nana-text-v1:l2:epoch1`. Returned provider model must be `text-embedding-3-small`. This application epoch identifies our preprocessing/configuration, not immutable provider weights. Never relabel MiniLM or assume dimension equality means compatibility.

Canonicalization matches current helpers: EVM-address redaction, NFKC, trim, whitespace collapse, Spanish lowercase; accents remain. Recipient input is `name: <normalized name>\ndescription: <normalized description>`, fact input `fact: <normalized fact>`; normalize the full constructed string again. Query is normalized raw query without a document prefix. Comparison key separately applies NFD and removes all Unicode marks. Preserve existing redaction limitations; free text may contain personal data or Solana/SNS identifiers. Do not send dedicated address, network, wallet/provenance/confirmation columns. Reject empty canonical content and >6000 UTF-8 bytes without truncation. Raw authenticated request-body cap16KiB; enforce while streaming, not trusting Content-Length. Oversized source stays saved and indexing fails.

Shared pure Deno helpers expose canonicalize/validate/normalize; backend deliberately duplicates only text/comparison contract with golden parity tests. Provider POST has fixed HTTPS URL, `{model:'text-embedding-3-small',dimensions:384,encoding_format:'float',input:canonicalText}` and one input per call. Reject redirects, non-2xx/unparseable responses, missing/wrong model, data length !=1, index !=0, length !=384, nonfinite elements or zero norm. L2-normalize and validate again. Fixed production destination cannot be overridden by request JSON or arbitrary deployment URL. Controlled fetch/env dependency injection is available only through test factory construction.

`POST embedding-query`: authenticate exact function-scoped bearer before reading body; body `{text,revision}` only. Return `{revision,dimensions:384,vector}` or sanitized 400/401/413/429/503/504. No user/source records or job controls. Three-second end-to-end deadline includes provider/admission/response, abort promptly, no retry. Backend validates identity/dimension/norm again and maps failure to existing unavailable outcome. Backend admission uses an owner-bound short SQL transaction before HTTP; no transaction is retained. Bound owner usage via durable owner+minute counters (default six query calls/minute); owner comes from authenticated backend/voice binding, never a free user field from HTTP.

`POST embedding-drain`: separate bearer; accepts empty object only, no table/model/URL. `verify_jwt=false` is explicit for both functions in config; handler auth is mandatory. Constant-time credential comparison via fixed-size cryptographic digest, fail closed on missing configuration. Query token never claims, drain token never queries. OpenAI/admin credential lives only in Edge; backend gets query token, pg_cron gets drain token. Handler core accepts injected RPC/fetch/clock; index.ts alone reads Deno env/serves.

Drain invocation45s, provider timeout15s, batch4, concurrency2, global run/job lease90s; abort when invocation budget expires and leave/release work for fenced reclaim. Shared SQL admission defaults60 requests/minute, 360000 canonical bytes/minute, with20 requests/120000 bytes reserved for query; drain cannot consume that reserve. In-flight reservations expire on crash and enforce global2 drain providers; query slots separately bounded. These are configurable operational ceilings, not guarantees of provider capacity. Verify actual provider spend/rate limits before enabling, lower ceilings if necessary. Safe logs contain only codes, counts, durations, attempts and queue age; never text, vectors, authorization, provider response bodies or raw thrown errors.

## 4. Retrieval snapshot contract (R1–R6)

Exact branch opens READ ONLY REPEATABLE READ under recipient_app plus app.user_id, DECLAREs an address-free owner+active cursor, FETCH128 per batch, runs the existing JavaScript comparison key over every row, and counts ALL matches before deciding. Keep only five display projections and one unique candidate; ambiguity count is uncapped. Iterate to exhaustion within a two-second total operational deadline; on timeout rollback and return unavailable, never declare uniqueness from a partial scan. Memory is bounded without imposing a new contact-count limit. Close transaction before any provider call. Output `{kind:'lexical',id,version,...evidence}` has no score/address. One match resolves, two require clarification, zero continues to inference. An exact miss never authorizes later semantic selection.

After obtaining a validated query vector, use ONE SQL statement per domain with MATERIALIZED `owner_active`, `gate` and ranked candidates. Scope ALL active owner rows, not just top-k or current network, before gating. Gate fails if any row has state !=ready, NULL/invalid vector, NULL revision or any mismatch among actual/desired/requested identities (use explicit equality of all three, and IS DISTINCT FROM for NULL-safe rejection). Candidate ranking uses the same `owner_active` CTE, returns address-free projections and existing deterministic ordering. Produce one envelope row `{complete,candidates}` even when candidates is empty; never confuse zero candidate rows with gate success. Control target/semantic acceptance is checked in that statement. An earlier gate is an optimization only. Keep existing lexical bonuses and prefix/qualified-name/description/relationship rules for complete snapshots, but calibrate their thresholds together.

Facts use the identical domain gate; pending/failed/incompatible facts produce unavailable, empty active facts produce empty success. Empty-domain optimization requires its own snapshot and cannot authorize a later result. Both recipient and fact races insert/reactivate/edit competitors during HTTP and after optimistic precheck; final snapshot must observe pending and refuse semantics. Changes after the final selection snapshot are handled by existing selected-recipient ID/version/address/network revalidation. Preview, explicit confirmation, idempotency and ambiguous-payment outcomes remain unchanged. No new HTTP fields; internal discriminated unions and existing tool outcomes carry saved/unavailable/clarification semantics. Uncalibrated semantics remains clarification-only even on a ready domain.

## 5. Safe promotion contract (L6, I6)

Dormant migrations preserve all actual vector identities; old writers/readers remain deployed until the full candidate image and handlers pass verification. Application sublayers are inert by default: transitional MEMORY_EMBEDDING_MODE=legacy keeps existing readers/writers and local-model startup unchanged while dormant. Automatic paths are selected only by explicit mode plus activated SQL state; mismatch fails closed before mutation/search. Add automatic operations behind that selector before replacing call sites. Never infer activation merely from nullable columns or missing credentials. Legacy mode is a temporary pre-cutover compatibility path, never an inference fallback after activation; after activation it refuses reads/writes. Local fixture activation is explicit and isolated. Remove legacy generators/downloads only in post-promotion cleanup after the automatic path is proven; before then automatic mode simply skips those startup hooks. Every partial PR must demonstrate unchanged default dormant behavior.

Before concrete remote approval: pass both migration chains, PG17 compatibility, backend/Edge/E2E/corpus; prepare migration diff/dry-run, image SHAs, function bundle checksums, grants, credential NAMES/presence, one scheduler adapter, capacity and rollback procedure. Model reversal/backfill and destructive schema removal require separate review.
