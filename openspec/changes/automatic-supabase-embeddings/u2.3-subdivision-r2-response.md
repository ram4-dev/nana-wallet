## C1: reservation identity, ownership, lifecycle and pause

Disposition: resolved for design review through explicit internal signatures, immutable reservation binding and assigned proof. The fixed two-argument admission/start sketches do not carry enough identity across separate transactions. R2 widens internal admission/start arguments rather than relying on session-local state, FIFO reservation selection or an implicit current request. Existing completion SQL023 remains unchanged; a new job-transition trigger adds capacity cleanup without copying/replacing the 59-line completion function in both chains.

- U2.3b1 creates private reservations/owner-minute accounting and its atomic helper; b2 implements bound admission and grants the query branch narrowly to the backend's existing `recipient_app` context. It tests actual SQL under the production `withUserTransaction` pattern. The public admission RPC accepts no owner argument. The backend must derive that context from HTTP auth or trusted voice binding; Edge ignores user owner headers/JSON. The GUC is the existing backend trust boundary, not a credential accepted from HTTP or proof against a malicious privileged database client.
- U2.3c implements real reservation consumption and attempt/query starts. A single atomic transition from RESERVED to STARTED, bound to the current job/claim/run, is the only provider-call authorization. Duplicates return `already_started`, never a second provider permission. Request/byte/owner charges remain spent even when reservation use fails or expires. A reserved-but-never-started job spends no provider attempt.
- U2.3d installs transition cleanup and a token-bound finish RPC. Completion/failure release in-flight occupancy after known completion. Invalidation/pause release unused reservations; already-started requests retain occupancy until explicit transport finalization or bounded expiry. Late stale completion still calls finish in the adapter's finally path; it cannot release a newer claim's reservation. This avoids recycling a slot merely because the source was edited while HTTP is outstanding.
- U2.3f implements pause and bounded defer as separate committed RPCs. Pause locks only control, marks any run unusable and commits. A live STARTED query reservation can also authorize a global pause with NULL run, so query faults do not depend on an active drain run. Defer subsequently locks jobs with SKIP LOCKED and then reads/pins control; it never waits for a source while holding control/job. Claims get an additive function replacement with job-then-control revalidation. Tests use the existing completion primitive and two real connections, covering both orders and expiry after waits. The reviewer did not find an existing deadlock; R2 prevents introducing the proposed inversion.

The exact interfaces, lock order, slot lifetimes, grants and per-layer file budgets are in the replacement subdivision. Future U3.3/U4.1/U4.2/U5.4 packet updates must propagate these internal SQL signatures and the opaque backend-to-Edge query-reservation header. User-facing HTTP payloads, source business schemas and product defaults do not change. Those supporting artifacts are outside this executor's ownership and were not edited.

## C2: crash after fifth STARTED attempt

Disposition: resolved for design review by U2.3e, not deferred to U2.4. SQL022 deliberately selects `attempts<5`; SQL023 requires a live lease for publication. A fifth-start crash therefore needs a cleanup path that does not pretend to be a live failure result.

U2.3e adds `embedding_recover_exhausted(requested_limit)` in its own mirrored additive migration. It discovers at most four exhausted expired candidates without job locks, acquires source then job with SKIP LOCKED, and rechecks exact owner/kind/source/incarnation/generation/revision and lease expiry using `clock_timestamp()`. It terminalizes only that matching pending source and job with `attempts_exhausted`; a changed/deleted/new-incarnation source is never failed. Historical obsolete work may be superseded. It accepts no success vector and cannot create attempt six or reset attempts. Explicit operator retry remains the only path to a new generation.

Its runtime suite must drive five actual admit → start → transient fail cycles, except the fifth outcome is withheld to simulate a crash. Before expiry recovery is a no-op; after expiry real recovery marks the matching generation failed. Then claim/start refuse attempt six, a stale old result remains fenced, healthy work progresses and operator retry creates fresh indexing work with unchanged business/history/policy. These controls run for recipient and fact on both independent fresh migration chains, including source-change and locked-source races. Fixture-setting attempts to five is allowed only as an additional corruption/boundary case, never as the sole C2 proof. The later Edge drain must call this bounded recovery in a separate committed RPC before normal begin/claim; U2.3e proves that SQL orchestration locally now, while U4 proves the actual handler later.
