## Native review candidate and delivery discipline

The native bounded review candidate is **one work-unit commit**, or the PR slice that commit belongs to
when review is deferred — never a checkbox, never a task line, and never the accumulated
`feat/solana-operational` branch. All source-mutating normalizers must run **before** the candidate is
frozen; after the freeze only check-only commands may run (design §12.3).

```text
npm run lint          # the only source-mutating normalizer; must be convergent (a second run is a no-op)
npm run typecheck
npm run build
npm test              # with docker compose up -d db
npm run eval
(cd apps/nana-wallet && npm run lint && npm run typecheck && npm test)
```

`openspec/config.yaml` declares `formatter: false`, so there is no format step. Any byte, path, or mode
change after the freeze invalidates the receipt and requires re-normalization plus a new review of the
new bytes. The receipt records the frozen commit SHA, an empty `git status --porcelain`, the exact
commands and results, and the baseline comparison by test name.

- [ ] **Freeze the candidate with normalization complete.** Run every normalizer above to convergence, re-snapshot the frozen work-unit commit, and confirm an empty `git status --porcelain`; after this point only check-only commands may run. Stop and report rather than editing code at this stage. <!-- sdd-owner: implementation -->
