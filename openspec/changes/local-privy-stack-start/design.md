# Design

Use a small Node launcher and a dedicated development image that compiles the backend once during its build. API, worker, and both sidecars reuse that image without starting concurrent TypeScript compilers. The initial runtime experiment with per-container compilation caused a real OOM kill; image compilation avoids that peak without stopping other projects. Use a non-secret Compose config referencing environment variable names, with explicit service credential allowlists, random loopback API/signaling ports, and configurable fixed RTC media ports (LiveKit requires advertised ports).

Default configuration is the repository's linked Supabase metadata under `supabase/.temp`; in a Git worktree, locate the common checkout's metadata if absent locally. Validate the linked ref and credential-free pooler URL against the project ref derived from Vault's `NANA_SUPABASE_URL` before combining the URL with Vault's `SUPABASE_PASSWORD_NANA_WALLET`. Require SSL and never use local DB fallback. Use only read-only startup database probes.

Use Supabase's public CA with `sslmode=verify-full` and a read-only certificate-file mount in API/worker. Keep runtime state in the common checkout's ignored `.cache/dev-stack` so worktree/main transitions preserve binding keys, signer token, and owned process identity. A frontend source-path change restarts only the owned frontend.

Retrieve public Privy verification keys from the official SDK's `https://api.privy.io/v1/apps/{appId}/jwks.json` endpoint and export all ES256 keys as a PEM bundle; the current backend supports multiple keys. Generate and retain a local Ed25519 conversation-binding pair using restricted ignored storage, so it remains stable across launcher restarts. Supply only the binding public key to the worker. Provision the Vault authorization key into a restricted file mounted only in signer sidecars; API/worker receive a signer URL/token, never that key. Do not read existing `.env` contents.

Frontend Vite config accepts `NANA_API_PROXY_TARGET` and `NANA_LIVEKIT_PROXY_TARGET` as opt-in loopback HTTP/WS targets. It proxies `/api` and `/livekit`, stripping only the corresponding prefix. The launcher injects `VITE_API_URL=/api`, `VITE_AGENT_BACKEND=1`, `VITE_E2E_REAL_BACKEND=1`, `VITE_LIVEKIT_TOKEN_SOURCE=local`, and Vault's public app ID into the frontend process; no other backend credentials enter its environment.

Keep Portless proxy ownership global: reuse correct HTTPS/443, never silently downgrade, preserve unrelated routes. When necessary use the normal Portless authorization path, or macOS administrator authorization with Portless daemon mode (not privileged `nohup`). Detect name ownership before replacing only the requested frontend route. A changed route from the current ad hoc Vite process is explicitly within user scope.

Readiness checks use Node HTTPS with the Portless CA (never `rejectUnauthorized:false`), expected unauthenticated binding response, signaling WebSocket upgrade with a disposable locally signed token and scoped room cleanup, worker registration evidence, sidecar reachability/capability, and remote read-only DB query. Browser login/audio and real Privy permissions are distinct manual checks, not inferred from health 200. Synthetic tests use local disposable DB/LiveKit rather than the remote target.
